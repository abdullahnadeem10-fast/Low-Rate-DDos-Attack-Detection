# Phase 3 — Progress and handoff

## 2026-11-04: Started the offline pilot

- Created `phase 3`, this `plan` folder, a live checklist, source scripts and an evidence directory. The local `.venv` runs on Windows; no system software was installed. WSL is not installed and the live lab has not been set up.
- Used the [UNB publisher documentation](https://www.unb.ca/cic/datasets/ids-2017.html) for the schedule, endpoint inventory and dataset citation. The official download page returned a form/server error; the pilot used a public mirror pinned to revision `811c007f08d693a8a8b4226c197c138391806ce6`. The Monday file was requested with HTTP Range `0-33554431`; the server returned `206` and the matching Content-Range. Only that benign prefix was parsed. The partial trailing 100 bytes were discarded so the packet reader received complete blocks.
- The synthetic fixture passed checks for packet direction, captured byte counts, idle seconds, history reset and lack of future influence. The real input covers 635.357 seconds and contains 54,632 readable frames. The chosen active benign LDAP endpoint contributed 2,516 TCP frames, producing 630 one-second feature windows. The planned HTTP/HTTPS endpoints did not appear in the prefix. The processing script reported 3.941 seconds including the smoke model, excluding process startup and download; not an extrapolation to a full capture.
- A benign-only Isolation Forest fit, calibration and scoring pass completed on chronological blocks of the same Monday prefix, separated by five-second gaps. It emitted 6 alerts in 153 later windows. This is a pipeline diagnostic with one service and one capture; it is not a final FPR, not the Phase 2 hybrid or full calibration protocol, and says nothing about attack recall or real-time delay. The 22 out-of-order timestamps can be aggregated offline by event time; live handling of late packets remains to be designed and tested.
- The full flow-label ZIP matched the mirror's SHA-256 and is stored under `data/quarantine/`. The audit opened **only** the allowlisted Friday DDoS CSV member. It counted 97,718 benign and 128,027 DDoS rows. All 225,745 timestamps are minute-only, 50,023 directed five-tuple/time keys repeat, and no exact key had conflicting labels in this member. The attack timestamps as written span `03:56` to `04:16`, while UNB's schedule lists the attack in the afternoon. Treat the apparent 12-hour difference as a hypothesis, not a validated clock conversion. Duplicate keys are not by themselves proof of duplicate flows. No packet labels have been assigned from these values.
- Wednesday raw captures and the external dataset were not fetched. Other members of the flow-label archive, including Wednesday, were not opened for development. No live attack traffic was generated and no final model was trained.
